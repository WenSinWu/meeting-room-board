標準開工儀式

1 一句話2 找碴3 被訪談4 開工儀式5 盯計畫6 放行7 點交8 存證
目標git init → /init → 補規範 → commit

怎麼做

STEP 1

退出 Claude，初始化 Git

在 Claude Code 裡輸入 /exit 退出，回到 PowerShell 執行：

git init
git add spec.md
git commit -m "初始化：加入需求規格"

⚠️ 第一次 commit 若被要求設定身分，先執行下面兩行（換成你自己的名字和 email），再重跑上面的 commit：

git config --global user.name "你的名字"
git config --global user.email "你的email"
STEP 2

重新啟動 Claude 並產生 CLAUDE.md

claude

進入後執行內建指令：

/init
STEP 3

先猜：你會立哪三條規矩？　⏱️ 60 秒

下一步要幫這個專案補上開發規範。先不要往下看——想像你是工地主任，要在 CLAUDE.md 立三條施工規矩，你會寫哪三條？寫在紙上。

提示方向：檔案怎麼管？介面與註解用什麼語言？它每次改完要跟你交代什麼？

STEP 4

補上專案開發規範

請根據 spec.md 更新 CLAUDE.md，加入以下開發規範：
- 本專案為單一 HTML 檔案，檔名固定為 index.html，禁止拆分多檔、禁止引入外部框架
- 所有介面文字與程式註解使用繁體中文
- 每次修改後，用一句話說明改了什麼

對答案：對照上面三條規範，圈出你沒想到的那條。特別注意「檔名固定為 index.html」這半句——它看起來囉嗦，卻是第九、十章不出事的保險絲：後面兩章的所有素材與測試都認這個檔名。防呆句的價值，就是在你想不到的地方先把路封死。

STEP 5

提交這個里程碑

請先用 git status 看目前有哪些變更，再把所有變更加入 git 並 commit，
訊息：「加入專案開發規範」

（為什麼是「所有變更」而不是只加 CLAUDE.md？先看 git status 就知道——Step 4 更新 CLAUDE.md 時，Claude 可能順手也調整了 spec.md。）

Claude 執行 git 指令前會請求你的核准——這是權限模式在保護你（第三章學過）。

📦 這一關的產物（後面會一直用到）
.git/ ＋ spec.md ＋ CLAUDE.md 的專案骨架，以及前兩筆 commit——第九、十章全部蓋在這個骨架上。

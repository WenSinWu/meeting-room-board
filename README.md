# 會議室預約看板

純前端的會議室預約工具：以「週檢視」呈現單一會議室的預約狀況，可新增、編輯、刪除預約，並自動擋下時段衝突。無後端、無登入、不依賴任何外部框架或 CDN，資料存在瀏覽器本機。

> 本專案為 Lab 6 教學專案。需求依據為 [spec.md](spec.md)；`Lab6_1.html` … `Lab6_8.html` 是教學講義，**不是**產品程式碼。

## 功能清單

- **週檢視看板**：日期為橫軸、時段為縱軸，一次顯示一間會議室的一週預約。
- **多會議室切換**：預設 3 間（最多 5 間），以分頁切換；名稱可在「設定」中編輯。
- **週次導覽**：上一週／本週／下一週；可勾選「顯示週末」。
- **新增／編輯預約**：欄位為會議室、日期、開始與結束時間、主題、預約人／備註。
- **衝突檢查**：同會議室、同日期、時間區間有交集即拒絕（新增與編輯皆檢查）；首尾相接（如 10:00–11:00 與 11:00–12:00）不算衝突。
- **刪除預約**：需二次確認。
- **可調整設定**：工作時段起迄（預設 09:00–18:00）、時段單位（預設 30 分鐘）、會議室名稱。
- **匯出／匯入 JSON**：作為唯一的完整備份途徑；匯入前會確認覆蓋，格式錯誤時不會破壞現有資料。
- **匯出 CSV**：輸出人類可讀的預約清單（含 BOM，Excel 可正確顯示繁體中文）。

不在範圍內：週期性預約、月檢視、多會議室總覽、通知、行事曆串接等（見 spec.md 第 4 節）。

## 如何開啟使用

不需要安裝、建置或啟動伺服器：

1. 取得專案資料夾。
2. 直接以瀏覽器（建議最新版 Chrome／Edge／Firefox）開啟 `index.html`。

資料儲存在該瀏覽器的 `localStorage`（鍵名 `meeting-room-board.v1`）。注意：

- 換瀏覽器、換電腦或清除網站資料後，資料不會跟著走，請定期使用「匯出 JSON」備份。
- 以 `file://` 開啟與以 `http://` 開啟屬於不同來源，資料不會互通。

## 如何執行測試

沒有測試框架或指令列工具。以瀏覽器開啟 `test.html` 即可：

- 頁面頂端顯示總結果（全部通過為綠色、有失敗為紅色）。
- 下方表格列出每個案例的名稱、預期值、實際值與結果，失敗列會標紅。

目前測試對象是 `app.js` 內的衝突判斷函式（`overlaps`、`findConflict`、`toMin`），涵蓋完全相同、完全錯開、部分重疊、完全包含、首尾相接、不同會議室、不同日期等情境。要新增案例，在 `test.html` 的 `tests` 陣列加一筆 `{ name, expected, fn }` 即可。

## 檔案結構

```
.
├── index.html   # 主程式：畫面、樣式、資料層（localStorage）、匯出入與互動邏輯
├── app.js       # 純函式：時間轉換與衝突判斷（無 DOM／儲存依賴，供 index.html 與 test.html 共用）
├── test.html    # 衝突判斷的瀏覽器端測試頁
├── spec.md      # 需求規格書（含 14 條驗收標準與待確認事項）
├── CLAUDE.md    # 給 Claude Code 的專案規範
└── Lab6_*.html  # 教學講義（八關流程），非產品程式碼
```

## 開發須知

- 產品程式碼限定 `index.html`、`app.js`、`test.html` 三個檔案，不再拆檔、不引入外部框架。
- `app.js` 以一般 `<script>` 載入（非 ES module），函式皆為全域，因此可直接在 `file://` 下運作。
- 介面文字與程式註解使用繁體中文。
- 工作時段、時段單位、週末顯示、會議室名稱皆為可調整設定，勿寫死。
- 資料格式（`version: 1`）包含 `settings`、`rooms`、`bookings` 三個欄位；修改結構時請同步考量匯入舊資料的相容性。
